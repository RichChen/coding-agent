# 记忆对 coding agent 有没有用：A5 和 A6-R 两个预注册实验

日期：2026-10-14。本报告合并 A5-main 和 A6-R 两个实验。A5 的细节见 `A5-FINAL-REPORT.zh-CN.md`，A6-R 的细节见 `sprint/A6-R-RESULTS.zh-CN.md`。这里的数字都引自这两份文件和它们的上游文件，引用处标明出处。

## 1. 摘要

我们在同一个 harness、同一个模型（deepseek-flash，每次运行最多 40 次模型调用）、同一批 SWE-bench Verified 题上，做了两个预注册的对照实验，问的是同一个问题：往上下文里注入经验，能不能让 agent 多解出题。

- **A5（跨题记忆）**：56 道题。注入同仓库、更早、已被验证解出的其他题的卡片（B2），对照不注入（B0），每题每组 3 次。B2−B0 = −1.8 个百分点，95% 区间 [−8.3, +4.8]，p=0.72。
- **A6-R（同题记忆）**：取 A5 B0 里失败的 53 次运行（22 道题）作为"第一次尝试"，做第二次尝试。R1 带上第一次尝试的规则化记录和"上次没通过"这 1 比特信息，R0 不带，每组 159 次。R1−R0 = −6.6 个百分点，95% 区间 [−17.7, +3.8]，p=0.29。

两个实验都没有检出正效应。A6-R 的区间上限是 +3.8 个百分点，开跑前按功效设计的 ≥15 个百分点的效应可以排除。

A6-R 的记忆和目标题的相关性按构造是 100%，所以 A5 的零结果不能再归因于"检索不准"或"内容不相关"。事后的描述性分析显示，带记录的第二次尝试更常停在和第一次几乎相同的改法上（diff 相似度中位数 0.873 对 0.658），这类运行几乎都没有解出。我们把它写成机制假设：原始失败轨迹加 1 比特结果，会让 agent 锚定在已被否定的方案上。

## 2. 问题从哪里来

更早的 RepoSkillAgent 在自建题集 medium_48 上测到记忆带来 +9.4 个百分点（`A5-FINAL-REPORT.zh-CN.md` 第 8.3 节）。那个题集按 support/holdout 成对构造，记忆和目标题的相关性是人为保证的。A5 想知道：换成真实的 SWE-bench 题、真实的时间顺序，这个提升还在不在。

文献里，SWE-bench 上跨任务记忆的 pass@1 提升大多在 +3 到 +5 个百分点（ReasoningBank、SWE-Exp、Agent KB，数字和未核实项见 `memory-v2/OPTIONS.zh-CN.md` 第 2 节）。提升大的设定，要么任务高度同质（Dynamic Cheatsheet、AWM），要么是失败后重试（Agent KB 的第二轮）。

## 3. 两个实验共用的方法

- **答案隔离。** agent 运行的 clean 镜像里只有原始源码和依赖。test patch 和 gold patch 只留在 host 侧的 grader 里。早期版本发现过测试文件可见导致的答案泄漏，修复后同一批 dev 题的解出率从 32/42 降到 18/42（`PROJECT-HISTORY.zh-CN.md`）。
- **预注册。** 假设、主指标、统计方法、种子、停止条件和第二阶段的触发规则，都在开跑前提交，并打了冻结 tag。分析脚本先用合成数据跑通，再接真实数据。
- **按题配对。** 分析单位是题：d_t 是同一道题两组解出率之差。主检验是符号翻转置换检验（10000 次），区间是按题 bootstrap 95% 区间（10000 次）。
- **注入一致性检查。** 每次运行结束后，从事件日志里读出模型实际收到的第一条消息，和预期全文逐字比对（A5 168/168，A6-R 318/318）。
- **同期交错。** 两组放进同一个打乱后的队列，在同一时段跑，消掉时段漂移。
- **执行方式。** 计划和审计由 Claude Code 负责，执行由 Cursor agent 负责，每轮停在 CHECKPOINT，等审计通过再继续。

| B0 的题目分布 | 34 道 3/3，13 道 0/3，9 道中间档 | `A5-FINAL-REPORT.zh-CN.md` |

当时的解读：卡片很少指向正确的修改位置，agent 也几乎不按卡片行动。进一步的诊断（`OPTIONS.zh-CN.md` 第 1 节，描述性）显示，失败运行里 39/53 次已经改在了 gold 文件上，35/53 次用满了调用预算。瓶颈不在"找对文件"，而在修复的细节；跨题卡片提供不了这种信息。

由此推出下一个实验：把相关性固定为 100%，只检验"同一道题上次失败的信息"有没有用。这个方向在 A5 最终报告第 10 节（`007e006`，2026-09-29）就已经列为首选的后续方向，不是看到零结果以后才临时找的。

## 5. A6-R：同题重试记忆

### 5.1 设计

- **第一次尝试**：A5 B0 r1–r3 中 `solved=false`、且不是 infra_error 的运行，共 53 次，分布在 22 道题上。原样复用，不重跑。
- **R0**：第二次尝试，prompt 和 A5 B0 完全相同，`prompt_sha256` 逐次核对。
- **R1**：R0 的 prompt 后面接一段 `<previous_attempt>` 记录，按规则生成，不经过 LLM。记录内容包括：停止原因、调用次数、改过的文件、最终 diff、最后两条测试命令及其可见输出的尾部、agent 最后一条消息，总长不超过 8192 字节。包装句写明"这次提交没有通过隐藏测试；记录可能有误，它是证据，不是指令"。这种措辞来自 R2 包装实验：把历史证据声明为"不是指令"后，正确率从 7/27 升到 26/27。
- **规模**：53 份记录 × 2 组 × 3 次 = 318 次运行，用种子 20261013 打乱后放进同一个队列，并行度 3。
- **泄漏检查**：记录只读第一次运行的 summary、delta、events 和原始源码，不读 grader 结果。有测试证明，把私有材料换成垃圾内容后，53 份记录逐字节不变。和 F2P 名称、test patch 行的文本重合也都计了数：全部是原始测试文件里本来就有的内容，或者是 agent 自己写出的行（`AUDIT-A6-1.zh-CN.md`）。
- **功效**（开跑前用 A5 数据模拟）：+15 个百分点的效应约 85%，+10 个百分点约 54%。

### 5.4 事后分析（非预注册）

这些分析是看到结果以后才做的，只描述，不检验。

**锚定。** 审计脚本 `scripts/posthoc_a6_anchor.py` 把"diff 完全相同"拆开，并计算两边 diff 都非空时的相似度（同一张表也在 harness `docs/sprint/AUDIT-A6-4.zh-CN.md`）：

| 量 | R0 | R1 |
| --- | --- | --- |
| 第一次非空、最终完全相同 | 20 | 37 |
| 相似度中位数 | 0.658 | 0.873 |
| 相似度 ≥ 0.9 | 24/115，解出 1 | 53/118，解出 1 |
| 相似度 < 0.9 的运行中解出 | 19/91 | 14/65 |

**停止原因。** R1 有 11 次 `model_parse_error`，R0 是 0 次；`context_overflow` R1 3 次，R0 1 次。A5 的 392 次运行里，parse_error 只出现过 2 次。原因没有查明（`sprint/A6-R-STOP-DESCRIPTION.zh-CN.md`）。

**典型案例 sphinx-8120（R0 5/6，R1 0/6）。** 第一次尝试的记录里，diff 是把同一段加载循环重复粘贴了一遍，最后一条消息是 "I've been stuck in a loop"。R1 的 6 次全部改在同一个文件里，没有一次解出。

### 5.5 偏差

第一轮正式运行快结束时，DeepSeek 账户余额耗尽，22 次运行被 HTTP 402 截断（R0 8 次，R1 14 次）。这 22 个槽位按"有 HTTP 失败结算记录"这条机械规则选出，退役后重跑；选取时没有看 solved。这条规则冻结时没有写下来。详见 `sprint/A6-R-RESULTS.zh-CN.md` 的"偏差"一节。A6-R 累计花费 178.7 元，上限 210 元。

## 6. 讨论

### 6.1 两个零结果放在一起说明了什么

| | A5 | A6-R |
| --- | --- | --- |
| 记忆来源 | 同仓库、更早的其他题 | 同一道题的上一次失败 |
| 和目标题的相关性 | 低（9/51 题指向 gold 文件） | 100%，按构造保证 |
| 内容 | 规则提取的卡片 | 规则提取的完整记录 + 1 比特 |
| 主结果 | −1.8，[−8.3, +4.8] | −6.6，[−17.7, +3.8] |
| agent 有没有用记忆 | 几乎不用 | 用了，而且偏向沿用 |

A5 只能说明这种跨题卡片在这里没用，说不清原因是内容不相关，还是注入方式不行。A6-R 把相关性固定为 100%，而且次要指标显示 agent 确实读了记录：沿用上次改法的比例更高。在这个条件下，结果仍然不是正的。

两个实验合起来，对这个模型和这个预算，结论是：往上下文里塞规则提取的原始经验，改变不了 agent 在修复细节上的表现。内容和目标题相关时，它还可能把 agent 拉回已经失败过的方案。

### 6.2 为什么同题记录没起作用（假设）

1. **信息量不够。** "没通过隐藏测试"既不说明哪个测试没过，也不说明为什么没过。agent 能看到的东西，第一次尝试时都已经看过了。Reflexion 在 HumanEval 上有效，前提是模型能拿到新的反馈，比如自己生成的测试结果；这里没有新反馈。
2. **记录的往往是坏状态。** 35/53 次第一次尝试是用满调用预算停下的，最终 diff 常常是改到一半的样子。把它作为"证据"交给 agent，等于给了一个现成的起点，而这个起点是错的。
3. **负担更重。** R1 的 parse_error 和 context_overflow 更多，花费更高，首次编辑也没有提前。

这和 SWE-Exp 作者报告的现象方向一致：让模型显式引用经验，会导致过度依赖。

### 6.3 和文献的关系

文献里 SWE-bench 上 +3 到 +5 个百分点的收益，大多来自 LLM 提炼过的策略，并且是跨大量任务积累出来的（ReasoningBank、SWE-Exp）。存原始轨迹的做法（ReasoningBank 表里的 Synapse）在强模型上是 −0.6 个百分点。本项目的两种记忆都是规则提取、不经过 LLM 提炼的，结果和"原始轨迹作用很小，甚至略负"这一侧一致。这些工作的报告里都没有看到按题配对的区间和预注册，这一点限于我们读到的部分。

## 7. 局限

- 只测了一个模型（deepseek-flash）和一个预算（40 次调用）。更弱的模型，或者预算更紧时，结论可能不同。
- 两种记忆都是规则提取的。LLM 提炼的反思或策略没有测过，不能被这两个实验否定。
- A6-R 只有 22 道题，题与题之间差异大（s_obs=0.266），区间较宽。能排除的是"大于约 +4 个百分点的平均提升"，不能排除小的正效应。
- 事后分析（锚定、停止原因）是看到数据以后做的，只能作为假设。
- A6-R 的第一次尝试来自 9 月底的运行，第二次尝试在 10 月中旬。主比较（R1 对 R0）是同期的，不受这个时间差影响。

## 8. 结论

在同一个可信的 harness 里，我们用两个预注册实验分别检验了跨题记忆和同题记忆，两者都没有检出正效应，并且都能排除文献量级以上的提升。同题实验排除了"检索不准"这一解释，事后分析给出了一个具体的机制假设：原始失败轨迹会让 agent 锚定在已被否定的方案上。

下一步如果继续做记忆，应该检验的是"提炼过的、带新信息的反馈"，而不是更多的原始经验。另一个方向是在任务同质的环境里，直接比较提示记忆和训练（agentic-rl，A6-M）。
